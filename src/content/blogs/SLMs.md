## The Architecture at a Glance

Before diving into code, here's what we're building. A decoder-only transformer — the same fundamental architecture as GPT-2, GPT-3, and their successors. Just... smaller.

**Model Configuration:**

| Hyperparameter | Value |
|---|---|
| Vocabulary Size | 50,257 (GPT-2 tokenizer) |
| Context Window | 128 tokens |
| Transformer Layers | 6 |
| Attention Heads | 6 |
| Embedding Dimension | 384 |
| Dropout | 0.1 |
| Total Parameters | ~30 Million |

These numbers aren't arbitrary. The embedding dimension (384) must be divisible by the number of heads (6), giving each head a 64-dimensional subspace to specialize in. 6 layers gives the model enough depth to compose increasingly complex representations.

## Step 1: The Dataset — TinyStories

We need text data. But not just any text data — we need something a 30M parameter model can actually *learn* from.

This is the first insight that most tutorials skip: **model capacity and dataset complexity must match.** Training a 30M parameter model on Wikipedia or CommonCrawl produces mostly garbage. The model is too small to capture the complexity.

We use **TinyStories**, a dataset of ~2.1 million short stories generated by GPT-3.5 and GPT-4, written using only words that 3–4 year olds understand. It's simple language, simple grammar, simple narratives.

That simplicity is precisely why it works.

```python
from datasets import load_dataset

ds = load_dataset("roneneldan/TinyStories")
# ds['train'] has 2,119,719 examples
# ds['validation'] has 21,990 examples
```

The training split alone contains over 2 million stories. For a 30M parameter model, this is the goldilocks zone — enough data to prevent overfitting, simple enough to actually learn from.

## Step 2: Tokenization — Converting Text to Numbers

A model doesn't see words. It sees integer IDs. We need to map every piece of text to a sequence of numbers, and back again.

We use **tiktoken** with the `gpt2` encoding — the same tokenizer OpenAI built for GPT-2. It uses Byte Pair Encoding (BPE) and has a vocabulary of 50,257 tokens.

```python
import tiktoken
import numpy as np

enc = tiktoken.get_encoding("gpt2")

def process(example):
    ids = enc.encode_ordinary(example['text'])
    return {'ids': ids, 'len': len(ids)}

tokenized = ds.map(process, remove_columns=['text'], num_proc=8)
```

The real trick: we don't store data in RAM. We use `np.memmap` — memory-mapped binary files — to write all token IDs directly to disk. The training loop reads chunks on demand. This is how you handle datasets larger than your RAM.

```python
arr = np.memmap('train.bin', dtype=np.uint16, mode='w+', shape=(arr_len,))
```

Why `uint16`? Because the GPT-2 vocab has 50,256 tokens, which fits in an unsigned 16-bit integer (max: 65,535). That cuts storage size in half versus int32.

## Step 3: The Batch Generator

Language models are trained using **next-token prediction**. Given a sequence of tokens, predict what comes next.

The `get_batch` function randomly samples starting positions from our training data and creates (input, target) pairs where targets are the inputs shifted by one position:

```python
def get_batch(split):
    data = np.memmap('train.bin', dtype=np.uint16, mode='r')
    ix = torch.randint(len(data) - block_size, (batch_size,))
    x = torch.stack([torch.from_numpy((data[i:i+block_size]).astype(np.int64)) for i in ix])
    y = torch.stack([torch.from_numpy((data[i+1:i+1+block_size]).astype(np.int64)) for i in ix])
    return x, y
```

If input is `["Once", "upon", "a"]`, the target is `["upon", "a", "time"]`. The model learns to predict every next token simultaneously — 128 predictions per sample, 32 samples per batch = 4,096 learning signals per step.

## Step 4: The Architecture — Building a Transformer

This is the heart of the project. Four building blocks:

### LayerNorm

```python
class LayerNorm(nn.Module):
    def __init__(self, ndim, bias):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(ndim))
        self.bias = nn.Parameter(torch.zeros(ndim)) if bias else None
    def forward(self, x):
        return F.layer_norm(x, self.weight.shape, self.weight, self.bias, 1e-5)
```

Layer normalization stabilizes training by normalizing activations to zero mean, unit variance. We apply it *before* attention and the feedforward layer (Pre-LN), which is more training-stable than the original Post-LN transformer.

### Causal Self-Attention

```python
class CausalSelfAttention(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.c_attn = nn.Linear(config.n_embd, 3 * config.n_embd, bias=config.bias)
        self.c_proj = nn.Linear(config.n_embd, config.n_embd, bias=config.bias)
        self.flash = hasattr(F, 'scaled_dot_product_attention')
```

A single linear projection produces Q, K, and V simultaneously — `3 * n_embd` outputs split three ways. This is the "attention head" mechanism: each of the 6 heads attends to different aspects of the input.

The **causal mask** is the key constraint. Each position can only attend to *past* positions (including itself). This is what makes it a language *generator*: it never peeks at future tokens during training.

We use Flash Attention when available (`F.scaled_dot_product_attention`) — a memory-efficient fused kernel that's 2–4x faster than the naive implementation.

### MLP (Feed-Forward Block)

```python
class MLP(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.c_fc = nn.Linear(config.n_embd, 4 * config.n_embd, bias=config.bias)
        self.gelu = nn.GELU()
        self.c_proj = nn.Linear(4 * config.n_embd, config.n_embd, bias=config.bias)
```

Two linear layers with GELU activation in between. The intermediate dimension is 4× the embedding size — this is where the model stores its "knowledge". Attention decides *what* to focus on; the MLP processes *what to do* with that information.

### The Transformer Block

```python
class Block(nn.Module):
    def forward(self, x):
        x = x + self.attn(self.ln1(x))   # Attention sub-block with residual
        x = x + self.mlp(self.ln2(x))    # MLP sub-block with residual
        return x
```

Two sub-blocks, each with a residual connection (the `x + ...`). Residual connections are the reason deep networks can train at all — they create gradient highways that let information flow directly from any layer to any other.

### Weight Tying

```python
self.transformer.wte.weight = self.lm_head.weight
```

The embedding matrix (tokens → vectors, ~19M parameters) is shared with the output projection (vectors → logits). This works because both the input embedding and output "unembedding" need to represent the same token meanings. It also saves ~19M parameters.

This is the section most tutorials rush through. These choices matter enormously.

```python
learning_rate = 1e-4
max_iters = 20000
warmup_steps = 1000
min_lr = 5e-4
batch_size = 32
block_size = 128
gradient_accumulation_steps = 32
```

**Gradient accumulation** is the biggest practical trick here. Our logical batch size is `32 × 32 = 1,024` samples per weight update — but we only process 32 at a time. This simulates a large batch without the VRAM cost.

```python
loss = loss / gradient_accumulation_steps
scaler.scale(loss).backward()

if ((epoch + 1) % gradient_accumulation_steps == 0):
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=0.5)
    scaler.step(optimizer)
    optimizer.zero_grad(set_to_none=True)
```

**Gradient clipping** (`max_norm=0.5`) prevents exploding gradients — a common failure mode in early training. Without it, a single bad batch can send the model into an unrecoverable state.

**Mixed precision training** (`bfloat16` or `float16`) cuts memory usage nearly in half and speeds up computation on modern GPUs, with a `GradScaler` to handle the numerical instability of float16.

## Step 6: The Learning Rate Schedule — Warmup + Cosine Decay

```python
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=learning_rate,
    betas=(0.9, 0.95),
    weight_decay=0.1,
    eps=1e-9
)

scheduler_warmup = LinearLR(optimizer, total_iters=warmup_steps)
scheduler_decay = CosineAnnealingLR(optimizer, T_max=max_iters - warmup_steps, eta_min=min_lr)
scheduler = SequentialLR(optimizer, schedulers=[scheduler_warmup, scheduler_decay], milestones=[warmup_steps])
```

Two phases:

1. **Linear Warmup (0 → 1,000 steps):** LR linearly increases from 0 to `1e-4`. Randomly initialized weights produce unstable, large gradients early on. Starting with a tiny LR prevents the first few updates from catastrophically damaging the initialization.

2. **Cosine Annealing (1,000 → 20,000 steps):** LR follows a cosine curve from `1e-4` down to `5e-4`. Cosine annealing is smoother than step decay and helps the optimizer settle into sharp, narrow minima later in training.

**AdamW** (not Adam) includes decoupled weight decay (`0.1`) — it penalizes large weights without distorting the adaptive learning rate estimates. `beta2=0.95` (vs the default 0.999) makes the second moment more reactive, beneficial for transformers.

## Step 7: Training — Watching Numbers Drop

Here's what the loss looked like across 20,000 steps:

| Step | Train Loss | Val Loss |
|---|---|---|
| 500 | 9.44 | 9.45 |
| 2,000 | 6.68 | 6.68 |
| 5,000 | 4.28 | 4.29 |
| 10,000 | 3.19 | 3.19 |
| 15,000 | 2.67 | 2.68 |
| 20,000 | 2.39 | 2.39 |

A few things stand out:

**Train and validation loss track almost perfectly.** The model isn't overfitting. With 2.1 million training examples and only 30M parameters, the model capacity is well-matched to the dataset.

**The loss drops fast early, then slows.** This is universal in deep learning — the model first learns obvious patterns (sentence structure, common words), then gradually learns finer nuances.

**Loss of ~2.4 in perplexity terms is e^2.4 ≈ 11.** The model is roughly as surprised as if it had 11 equally likely choices at each token. For reference, GPT-2 (117M parameters) on this kind of data would achieve much lower — but 11 is already enough to generate plausible text.

The training took about 20 minutes on a Google Colab A100 GPU.

```python
sentence = "A little girl went to the woods"

print(enc.decode(y.squeeze().tolist()))
```

**Output:**
> *"A little girl went to the woods and he was looking at the animals and he saw a little boy with a big smile on its face. He knew she would never bring medicine before. One day, the girl called Jeff went for a walk. He saw something pretty in a nearby old structure. It was a kind of creature and he is leaning chillis and hiding. Lilly looked up at the octopus..."*

It's not perfect. The pronouns are confused ("he" for "she"), the plot meanders, the creature is hiding chillis. But look at what it *does* get right:

- Grammatically valid sentences
- Narrative structure (introduction → action → description)
- Named characters emerge spontaneously (Jeff, Lilly)
- Appropriate vocabulary for the domain

The `generate` function uses **top-k sampling** and **temperature** to control randomness:

```python
@torch.no_grad()
def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
    for _ in range(max_new_tokens):
        logits, _ = self(idx_cond)
        logits = logits[:, -1, :] / temperature
        if top_k is not None:
            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
            logits[logits < v[:, [-1]]] = -float('Inf')
        probs = F.softmax(logits, dim=-1)
        idx_next = torch.multinomial(probs, num_samples=1)
        idx = torch.cat((idx, idx_next), dim=1)
```

Temperature < 1.0 makes the model more conservative (picks high-probability tokens). Temperature > 1.0 makes it more creative (higher-probability among a wider set). Top-k restricts sampling to only the k most probable next tokens, preventing very low-probability nonsense.

## 5 Things This Project Taught Me That Papers Never Say

**1. Data quality matters more than you think.**

The reason TinyStories works is that its simplicity matches the model's capacity. I originally tried training on more complex text and the model made very slow progress. Aligning data complexity with model size is as important as the architecture itself.

**2. Gradient accumulation is essential on limited hardware.**

A batch size of 32 is too small for stable transformer training. But a logical batch of 1,024 (via 32 accumulation steps) works well. This is a practical trick that isn't intuitive until you've watched training diverge with small batches.

**3. Learning rate warmup is non-negotiable.**

Skip the warmup and the first few hundred steps can permanently damage your initialization. The model needs a gentle start before the full learning rate kicks in.

**4. Weight tying isn't just a memory trick.**

Sharing weights between the token embedding and the output head enforces a useful constraint: the model's internal representation of tokens is consistent from input to output. It tends to improve training stability, not just save parameters.

**5. Loss of 2.4 is actually impressive.**

Cross-entropy loss of 2.4 sounds abstract. But when you remember that random token prediction from 50,257 tokens gives a loss of ln(50257) ≈ 10.8, and our model achieves 2.4, it's learned to compress the distribution to about 4% of its original entropy. It has genuinely learned *something* about language.

## What's Next?

This model is a foundation, not a finished product. Here's where you can take it:

- **Scale up**: Double the layers and embedding dimension, train on more data. This is literally how GPT-2 was built.
- **Instruction fine-tuning**: Add examples of (instruction, response) pairs to teach the model to follow directions. This is what makes ChatGPT feel useful.
- **Retrieval-augmented generation (RAG)**: Give the model access to external documents so it can answer factual questions it wasn't trained on.
- **Domain-specific pretraining**: Train on medical text, legal text, or code, and build a domain expert from scratch.
